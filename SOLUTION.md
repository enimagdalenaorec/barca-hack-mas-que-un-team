# Solution — Telemetry-Driven Possession State Machine

This document describes the BAR-ATH possession pipeline, its rule-compliance position, and the
known limitations. The submission is generated by `python -m solution.make_submission`.

## 1. Rule compliance audit

**Audit basis:** `RULES.md` (Rule 1 and “the provided data is a starting point”), `FAQ.md` (Smart
Tagging, external data, hand labels), and `CHALLENGE.md` (possession definition and scope). Code
reviewed: `solution/tracking.py`, `solution/make_submission.py`, `solution/test_external.py`, and
`solution/external_games.py`.

### 1.1 No hand annotation or frame-level corrections (Rule 1)

**Confirmation: the submission code contains no manual frame-by-frame annotations, no hardcoded
possession intervals, and no per-frame corrections.** Every label is produced at runtime by
`build_possession_frame()`.

Evidence:

- `solution/tracking.py` contains no label table, no frame-keyed dictionary, and no branch on a
  specific frame or match clock. `build_possession_frame()` derives `dead` from geometry and
  events, writes sparse `team` anchors, then calls `_state_codes()` / `ffill()`.
- A search of the submission path finds no BAR-ATH frame constants and no graded-window constants
  such as `11185`, `90652`, `110808` or `190197` in `tracking.py`. In the submission path, the only
  frame values are the documented video/timecode alignment constants in `games.py` and
  `solution/timecode.py`; they translate clocks and do not assign possession.
- `solution/make_submission.py` is a pure serializer. It calls `build_possession_frame()` and writes
  `table[["frame", "state"]]`. There is no post-processing, manual patching, or segment editing.
- `tracking.py` and `make_submission.py` never read `evaluation/gt/*`, the private ground truth, or
  any human-produced BAR-ATH event data. The only event-like input is the provided Smart Tagging
  XML, which `FAQ.md` explicitly authorises.
- All thresholds are global physical or algorithmic parameters (`CONTACT_RADIUS_M`,
  `PHYSICS_TURN_DEG`, `CONTROL_MIN_FRAMES`, and so on). They are applied identically to every frame
  and every match; none selects a named frame or a manually chosen possession.
- Transparency note: `SET_PIECE_FALLBACK_S = 3.28` is a global fallback for the set-piece restart
  detector when the ball is not observable. It reflects the observed kickoff tagging convention
  that the restart is about 82 frames after the tag start; it is a global timing parameter, not a
  frame-level possession correction. Whenever the ball is visible, the restart is found from ball
  motion instead.

**Development-process caveat:** the code has no ground-truth dependency, but the rules also forbid
tuning on the public five minutes. Any hyperparameter selected by repeatedly scoring against that
window should be disclosed as a tuning decision. The submission path itself never reads the file;
a code audit alone cannot establish the full development history.

### 1.2 Smart Tagging anchors

**Confirmation: the use of Smart Tagging complies with the rule that improving provided data is
legitimate as long as it is produced by an algorithm.**

- `FAQ.md` states that Smart Tagging is automatic Metrica output, not ground truth, and that the
  intervals are phases, not possessions.
- `load_events()` parses the XML. `possession_anchors()` converts phases into sparse point anchors:
  attacking codes anchor the tagged team, defending codes anchor the opponent, and set pieces
  anchor at the detected restart. A `Team=N/A` set piece is resolved by
  `nearest_player_at_frames()` from the tracking. Conflicting tags are resolved by a fixed write
  order: defending, attacking, then set pieces.
- The code never copies a Smart Tagging interval as a possession label and never treats a phase as a
  possession. A phase is one piece of evidence; the final state also uses dead-ball geometry,
  physics/contact anchors, and temporal propagation.
- Every transformation is deterministic code. No human edits the XML, no phase is corrected by
  hand, and no frame-specific override exists.

- It downloads only `Sample_Game_1` and `Sample_Game_2` from
  `https://github.com/metrica-sports/sample-data`. These are public Metrica sample matches, not the

- It does not read `data/tactical/BAR-ATH_*`, `evaluation/gt/*`, or any BAR-ATH tracking, event, or

- The derived ground truth comes from Metrica’s own event stream for those external games. The

- **Methodological caveat:** the external ground truth and the external anchors both come from the

## 2. How the algorithm works

The pipeline is a deterministic, event-anchored state machine. It runs in five stages:

- **Dead-ball segmentation (`dead_ball_mask`).** A frame is dead when the visible ball is outside the
  pitch, or when an automatic `GOALS`/`SET PIECES` tag opens a stoppage window. Set-piece tags are
  not treated as dead for their full duration: `_restart_frame` finds the first sustained ball
  movement inside the pitch (at least 2 m/s for 3 consecutive frames, with a 3.28 s fallback), so
  only the lead-in is `D`. Missing ball observations remain unknown rather than dead, which lets
  the state machine bridge tracking gaps.

- **Sparse event anchors (`possession_anchors`).** Automatic Smart Tagging phases are converted into
  point-in-time team anchors rather than copied as possession intervals. Attacking codes anchor the
  tagged side, defending codes anchor the opponent, and `SET PIECES` anchor at the algorithmically
  detected restart. A `Team=N/A` set piece is resolved by the nearest tracked player to the ball
  at the restart frame. The write order (defending, attacking, set pieces) makes the most specific
  evidence win.

- **Turnover confirmation (`confirm_live_turnovers`).** A live event tag that changes possession
  is only accepted once the named side actually reaches the ball. The pass looks up to 20 frames
  (0.8 s) ahead for a live frame where that side has a player within `CONTACT_RADIUS_M = 1.5 m`.
  When support is later than the tag, the anchor moves to the first supported frame; when there is
  no support, it is dropped and the previous stable possession keeps filling. The move never
  crosses a dead-ball gap or another side's anchor. This stops a tackle or pass timestamp from
  creating a false turnover while the old side still controls the ball.

- **Physical evidence (`ball_telemetry`, `physics_anchors`, `contact_anchors`).** Ball speed is a
  centred rolling median; windowed before/after velocities give turn angle and speed change.
  `physics_anchors` flags a hard touch when the ball is within 1.5 m of a player, turns at least
  45°, is moving at least 4 m/s before the turn, and changes speed by at least 1.5 m/s.
  `contact_anchors` adds a sustained-control path: the nearest player must be within 1.5 m, at
  least 0.25 m closer than the runner-up, and satisfy the radius/speed gate for six consecutive
  frames. Both passes only fire on live frames and only when the nearest player’s team differs
  from the current state. Each accepted anchor records its reason (`physics_interception`,
  `contact_control`, and so on), so every transition remains traceable and auditable.

- **Temporal propagation and edge calibration (`_state_codes` / `ffill`).** The dense label
  sequence is assembled from two arrays: dead frames are written as `D`, accepted anchors as `H`
  or `A`, and pandas `ffill()` carries the last known state through occlusion, loose balls, and
  missing observations. Frames before the first anchor remain `X`. Two fixed global calibrations
  then run. `smooth_micro_possessions` absorbs `H`/`A` runs shorter than 18 frames into the
  previous state while preserving dead-ball windows and short runs backed by physics evidence.
  `extend_possession_tails` adds a 4-frame tail to each surviving possession, because an event
  timestamp marks the touch or challenge, not the instant control ends. These are global rules
  applied identically to every match, not hand corrections.

## 4. Biggest edge cases and next algorithmic enhancements

### 4.1 Edge case 1 — Aerial duels and deflections

The current contact test is a 2D Euclidean distance: `distance <= 1.5 m`. It has no ball-height or
player-reach model. A ball travelling above head height can project inside that radius, and a
header or chest deflection can produce exactly the sharp turn and speed change that
`physics_anchors` treats as an interception. `physics_anchors` also uses only the instantaneous
nearest player and has no post-touch control requirement. As a result, an aerial duel won without
subsequent control, or a deflection that does not intercept the pass, can flip possession — both
are explicitly excluded by `CHALLENGE.md`.

The `CONTACT_DOMINANCE_M = 0.25` threshold is also brittle in a crowded box. Several players can
sit within 0.25 m of one another, suppressing a valid control anchor; alternatively, a single
0.26 m leader can win the anchor even when the ball is in a crowd.

### 4.2 Edge case 2 — Passes into space and tracking loss

`ball_loose` is true only when the ball is faster than 4 m/s and no player is within 1.5 m. A slow
rolling ball outside 1.5 m is therefore neither loose nor contact. `contact_anchors` additionally
requires six consecutive frames of proximity. When a pass is played into empty space, the old
team’s label is forward-filled until the receiver is already within 1.5 m for six frames.

If the ball is missing — it is absent on roughly 41% of graded frames — `ball_seen` is false and no
physical anchor can fire at all. `ffill` then carries the old label through the flight and
possibly through the reception, until the next Smart Tagging anchor arrives. That produces stale
possession, over-long spells, and missed turnovers on long passes, clearances, and counterattacks.

### 4.3 Enhancement 1 — Momentum-integrated ball flight and probabilistic touch attribution

Replace the raw turn test with a state-space flight model. Use a Kalman filter with state
`x = [p_x, p_y, v_x, v_y]^T`, process model

```text
x_{t+1} = F x_t + w_t,    F = [[I, dt I], [0, I]]
z_t     = H x_t + v_t,    H = [I, 0]
```

and process noise driven by unmodelled acceleration. The filter predicts the ball through missing
observations and produces the innovation `nu_t = z_t - H x_{t|t-1}` and covariance `S_t`. A touch
is an unexplained impulse, detected by the normalized innovation squared
`nu_t^T S_t^{-1} nu_t` exceeding a chi-square threshold, rather than by a fixed 45-degree turn.
This separates a genuine change of ball motion from tracking noise and from a smooth flight.

Attribute the touch probabilistically. For each player `i`, compute the reachable ball position at
the touch time,

```text
||p_i + v_i dt - p_ball(t)|| <= r_reach + v_max dt
```

and assign

```text
pi_i = exp(-d_i^2 / (2 sigma^2)) / sum_j exp(-d_j^2 / (2 sigma^2)).
```

Require `pi_i` to dominate the runner-up and, critically, require **post-touch control**: the ball
must slow below the control threshold and remain within `CONTACT_RADIUS_M` for
`CONTROL_MIN_FRAMES`, or the player’s deceleration must be consistent with a trap. A deflection or
an aerial duel without that dwell is classified as “no change” and keeps the previous state. If a
height or ball-size cue is available, add a reach constraint; without it, the control dwell is the
main safeguard.

Implementation: add `ball_flight_filter()`, `touch_probabilities()`, and `control_dwell()`, and use
them to gate `physics_anchors` and `contact_anchors`. Keep the existing thresholds as fallbacks.

### 4.4 Enhancement 2 — Space-time reachability and Voronoi pitch control for loose balls

Replace the binary `loose`/`contact` gate with a continuous control field. For each player `i`,
predict position over a horizon `tau`:

```text
p_i(tau) = p_i + v_i tau + 0.5 a_i tau^2
```

with speed and acceleration caps. For the predicted ball trajectory `p_ball(tau)`, compute the
time to reach the ball:

```text
tau_i = min { tau >= 0 : ||p_i(tau) - p_ball(tau)|| <= r_control }.
```

If no solution exists, set `tau_i = infinity`. Define the control probability at the predicted
reception time (or integrated over the horizon) as

```text
P_i = exp(-tau_i / kappa) / sum_j exp(-tau_j / kappa).
```

The space-time Voronoi cell of player `i` is the set of ball positions where `tau_i` is minimal.
An anchor requires `P_i` above a threshold for a minimum dwell, with hysteresis. This assigns a
pass into empty space to the player who can actually reach it first, even if that player is 5–10 m
away now, and it handles slow rolling loose balls that the current binary gate misses. Use the
Kalman prediction from Enhancement 1 to bridge short tracking gaps. If the maximum control
probability is low, or the ball is unobserved beyond the horizon, keep the previous state or emit
`X` rather than forcing a turnover.

Implementation: add `reachability_field()` and `control_probability()`, and use them in
`contact_anchors` in place of the current nearest-distance gate. An HMM/Viterbi pass with transition
costs and a minimum-duration prior can then replace `ffill` as the final smoother; the current
`ffill` remains the deterministic fallback.

**Implemented (Phase 3).** `player_velocities()` derives velocity vectors with a five-frame finite
difference and a 12 m/s cap. `time_to_intercept()` solves the constant-velocity quadratic for the
first time a player enters the 1.5 m reach radius of the projected ball, inside a 1.2 s horizon.
`reachability_field()` reduces each team to its minimum TTI and applies a two-team softmax with
`kappa = 0.35 s`. The resulting field is used in three places:

* Team=N/A set pieces resolve to the confident TTI team, falling back to Euclidean nearest.
* Physics touches require kinematic agreement with the nearest player; the old override was
  rejected because it lowered IDSSE spellF1 from 0.5982 to 0.5731.
* A loose-ball veto removes anchors while the ball is faster than 4 m/s and a confident field
  (`P >= 0.75`, `TTI <= 0.4 s`) names a different team, so possession only flips once a player
  actually controls the ball.

Predicted loose-ball anchors (`loose_ball_anchors`) remain available but are off by default:
early anchors were less reliable than the event stream. The 18-frame smoother also protects short
runs backed by a physics anchor. Phase 3 measured macro-F1 0.8617 and spellF1 **0.6064** on IDSSE
`J03WOH` (377 predicted spells versus 402 GT), with BAR-ATH at 0.5111. The residual gap was
boundary alignment, which Phase 4 addresses.

### 4.5 Implemented (Phase 4) — boundary calibration

**Diagnosis at IoU ≥ 0.5, before calibration.** Matched starts were nearly centred (mean −1.1
frames, median 0), but matched ends were early (mean −7.4, median −4), so spells were about 6.3
frames too short. The error was not uniform: ends into a dead ball were especially early (mean
−22.1, median −7), while starts after a dead ball were late (mean +1.5, median +1, p90 +3). After
the first two calibrations, the worst remaining errors were false live turnovers: a `pass`,
`tackle` or `interception` tag flipped possession while the old side still had the ball. At the
event frame, only 36% of flipping `pass` anchors, 24% of `tackle` anchors and 21% of `interception`
anchors matched the official label; set-piece restarts were 91% correct. One example: a `tackle`
anchor at frame 18748 flipped to the away side while the nearest away player was 1.76 m from the
ball with no kinematic support, and the official home possession continued for another 218 frames.

**Implemented hacks (all deterministic, no frame-specific rules):**

1. **Restart lead — `SET_PIECE_ANCHOR_LEAD_FRAMES = 2`.** The restart detector waits for three
   moving frames, so its anchor lands about two frames after the official restart. Pulling it back
   closes that detector latency; the anchor is only moved if the earlier frame is live.
2. **Possession tail — `POSSESSION_TAIL_FRAMES = 4`.** After smoothing, each surviving `H`/`A`
   spell is extended by four frames into the following live/dead state. This reflects that an event
   timestamp marks the strike or challenge, not the instant control is lost. The extension never
   writes into `X`. Tail 4 was chosen over tail 3 because tail 3 gains 0.0011 IDSSE spellF1 but
   loses 0.0111 on BAR-ATH; tail 4 is the robust setting across both.
3. **Turnover confirmation — `confirm_live_turnovers`.** A live event anchor that changes
   possession now needs physical support: within the next 20 frames (0.8 s) the named side must
   have a player within `CONTACT_RADIUS_M = 1.5 m`. If support arrives later than the tag, the
   anchor moves to the first supported frame; if there is no support, the anchor is dropped. Moves
   never cross a dead-ball gap or an opposite side's anchor. The confirmation pass updates its
   running forward-filled state, so a later same-side anchor can still re-establish possession
   once it is supported. This is the possession-hysteresis idea expressed as a physical
   confirmation window rather than a second distance threshold.

### 4.6 Suggested order

1. **Space-time reachability first.** It addresses the larger exposure: 41% missing-ball frames,
   passes into space, and the slow-loose-ball dead zone.
2. **Momentum/touch attribution second.** It improves precision in aerial duels, deflections, and
   crowded boxes, where the current physics pass can create false turnovers.
